问题 1：CancelledError（根治）
根因：langgraph dev 默认 reload=True，uvicorn 递归监视项目目录下所有 *.py（已核实 uvicorn 0.54 的 FileFilter.includes=["*.py"]）。而 code_agent 的本职工作就是把生成的分析脚本写进被监视的 tmp/：create_file(*.py) + 多次 str_replace 重写 → 每次写入触发热重载 → 进程重启 → 在跑的 run 被杀 → CancelledError + cannot schedule new futures after interpreter shutdown。这就解释了为什么偏偏每次都是 code_agent：crawler 写 .json/.md、chat 写 .md，只有 code_agent 写 .py。时间线完全吻合：sh_index_ta_20260930.py mtime 14:52:13 → run 1 日志止于 14:52:33 → run 2 于 14:52:57 重启续跑。修复：langgraph-dev.ps1 默认追加 --no-reload（跑 agent 期间本就不需要热重载），并加 -Watch 开关供"纯改代码、不跑 agent"时显式启用。参数拼装 4 种场景已验证：默认→dev --no-reload、-Watch→dev、--port 2025→不会重复加、显式 --no-reload→不重复。
上一轮的两个加固这次确实生效了：日志里 [idempotent] step 3/5 artifact already on disk → skip re-run 让续跑没有重做 step 3，run_started_at 的 mtime 过滤也正确只认本次 run 的产物。它们把"被杀后的损失"降到了最低，但真正让进程被杀的元凶是热重载——这次从源头关掉。
